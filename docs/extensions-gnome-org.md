# Publishing on extensions.gnome.org

Window Magnet is prepared for [extensions.gnome.org](https://extensions.gnome.org) (EGO). This page is the checklist
for an upload; nothing here uploads anything by itself.

## Build the zip

```sh
scripts/pack.sh          # dist/window-magnet@maximeallanic.github.io.shell-extension.zip
```

`scripts/pack.sh` runs `gnome-extensions pack` with the extra modules, the translations (`po/` compiled to
`locale/<lang>/LC_MESSAGES/window-magnet.mo`) and the schema, then:

- `scripts/normalize-zip.py` makes the zip reproducible (sorted entries, fixed timestamps, fixed permissions) and
  drops `schemas/gschemas.compiled`: GNOME Shell 44 and later compile the schema when the extension is installed, and
  the EGO review asks for the XML only;
- `scripts/check-zip.py` checks the result against the review rules listed below and fails on any violation.

The zip contains only: `metadata.json`, `extension.js`, `prefs.js`, the other `*.js` modules, `m3e/*.js`,
`schemas/org.gnome.shell.extensions.window-magnet.gschema.xml` and `locale/*/LC_MESSAGES/window-magnet.mo`.

## What the review looks at, and where it is handled

Rules from the [EGO review guidelines](https://gjs.guide/extensions/review-guidelines/review-guidelines.html):

| Rule | In Window Magnet |
|------|------------------|
| Nothing created or connected before `enable()`, everything undone in `disable()` | `extension.js`: settings, signals, springs and the tab placer are created in `enable()`; `disable()` disconnects every signal, stops the springs, resets actor offsets and destroys the tab placer (its GLib timeouts included). The end-to-end test disables the extension in the middle of a drag. |
| No objects stored at module scope | Module scope holds only constants and pure functions. |
| No deprecated modules (`Lang`, `Mainloop`, `ByteArray`), ES modules only | Checked by `scripts/check-zip.py`. |
| `prefs.js` must not import Shell-process libraries (`St`, `Clutter`, `Meta`, `Shell`, `ui/*`), and the extension must not import GTK | Checked by `scripts/check-zip.py`. |
| `metadata.json`: `uuid` matches the zip, `shell-version` lists stable majors only, `url` set, no `version` key (EGO sets it), no `session-modes` when it would only list `user` | Checked by `scripts/check-zip.py`. `version-name` carries the human version (`0.1.0`). |
| GSettings schema in `schemas/`, id under `org.gnome.shell.extensions`, XML included | `org.gnome.shell.extensions.window-magnet`; the compiled file is left out (Shell 44+). |
| No binaries, no scripts, no `.po`/`.pot` in the zip, no minified code | Only the files listed above are packed. |
| No subprocess, no network, no file access unless needed | Window Magnet uses none of them. |
| Vendored third-party code must be unmodified and its origin stated | `extension/m3e/` is an unmodified copy, origin and SHA-256 in `vendor/m3e.lock`, licences in `NOTICE.md`. |
| Files under 500 lines, readable code | All sources are under 500 lines. |

## Uploading

1. Run `tests/run.sh` and the nested end-to-end test (`dev/nested/nested.sh --scenario e2e --out DIR`), both green.
2. Sign in at <https://extensions.gnome.org/accounts/login/> (create an account first if needed).
3. Open <https://extensions.gnome.org/upload/>, choose the zip from `dist/`, accept the licence terms (the extension
   is MIT, compatible with the GPL-2.0-or-later requirement of EGO) and submit.
4. The extension waits for a human review. Answer the reviewer's comments, fix, bump nothing by hand (EGO numbers
   the versions itself) and upload the new zip.
5. Once accepted, add the EGO link to the README (*Install* section) and to the repository's About box.

For each later version: update `shell-version` when a new GNOME Shell major has been tested, run
`scripts/release.sh X.Y.Z`, tag, let the release workflow publish the GitHub release, then upload the same zip to EGO.
